# MakerWorld CAD Studio

Parametric, print-ready product design in OpenSCAD, built to the standards in
the studio brief (`CLAUDE.md`, supplied via session config).

Each product lives in its own folder under `projects/` and is validated by a
scripted parameter matrix before it is ever called finished.

## Layout

```
tools/scadkit.py          render + mesh-validation harness (shared by all projects)
projects/<product>/
    src/<product>.scad    the model; self-contained so it drops straight into
                          MakerWorld's Parametric Model Maker
    validation.json       the parameter matrix and its pass/fail expectations
    exports/              generated meshes (regenerated by the harness)
    previews/            generated PNGs for design review
    docs/                README, dimensions, validation report, listing copy
```

## Toolchain

| Tool | Version | Notes |
| --- | --- | --- |
| OpenSCAD | 2021.01 | Stable release; matches the feature set MakerWorld's Parametric Model Maker accepts. Nightly-only features are deliberately avoided. |
| trimesh | 5.1.0 | Mesh validation (watertightness, body count, degenerate faces). |
| scipy | 1.17.1 | Required by trimesh for connected-component counting. |
| xvfb | — | OpenSCAD 2021.01 needs an X server for PNG export; STL export does not. |

Install on a bare box:

```bash
apt-get install -y openscad xvfb
pip3 install numpy scipy trimesh
```

## Using the harness

Run a product's full validation matrix — this is the gate a design must pass:

```bash
python3 tools/scadkit.py matrix projects/<product>/validation.json
```

It exports every case, inspects every mesh, prints a PASS/FAIL table, and exits
non-zero if anything fails. Add `--previews` to also render PNGs for visual
review (brief §42 — mesh statistics alone are not evidence of a good design).

One-off operations:

```bash
python3 tools/scadkit.py render  src/part.scad out.stl -D wall_thickness=3.0
python3 tools/scadkit.py preview src/part.scad out.png --camera iso
python3 tools/scadkit.py check   out.stl --watertight --bodies 1
```

Named cameras: `iso`, `iso_rear`, `front`, `rear`, `left`, `right`, `top`, `bottom`.

### validation.json

```json
{
  "name": "product name",
  "scad": "src/product.scad",
  "cases": [
    {
      "name": "default",
      "params": { "wall_thickness": 2.4 },
      "expect": { "watertight": true, "bodies": 1, "max_bbox": [180, 180, 180] }
    }
  ]
}
```

Supported expectations: `watertight`, `bodies`, `max_bbox`, `min_bbox`,
`max_volume_cm3`, `no_degenerate` (on by default). The matrix should cover the
corners of the parameter space and every shipped preset, not just the default
(brief §41).

## Validation status vocabulary

The brief (§3 Phase F, §56) requires these to stay honest:

- **CAD-validated** — compiles, renders, exports, mesh checks pass.
- **Prototype-ready** — CAD-validated, and the design review found no blocking issues.
- **Print-tested** — an actual print exists and was measured or used.

A model is never described as fitting a real object until a physical print says so.
